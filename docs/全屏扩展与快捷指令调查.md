# 全屏截图翻译与快捷指令（1.2）

## 根据什么修改

用户提供的 iTranscreen 快捷指令只有“截屏”和“与 iTranscreen 共享”两个动作。这是系统共享/操作扩展入口，与之前的 App Intent `SnippetIntent` 结果卡片不同。

iTranscreen 的[公开网站](https://www.itranscreen.com/)及 [App Store 页面](https://apps.apple.com/cn/app/id1663139919)也介绍了快捷指令沉浸式截图翻译。没有找到其公开源码，未取得或破解 App Store 二进制；因此不把推断写成已确认的内部实现。

苹果的 [Action Extension 指南](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Action.html)明确说明：

> If you want to present your iOS Action extension full screen, add the following key-value pair to the extension’s NSExtension dictionary: `NSExtensionActionWantsFullScreenPresentation` / `true`.

普通 [Share Extension](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Share.html)的 UI 有尺寸限制。因此本次新增的是通过共享入口运行的 **Action Extension**，扩展点为 `com.apple.ui-services`，全屏键放在 `NSExtension` 字典中，使用自定义 `UIViewController` 承载 SwiftUI。

## 实际流程

```text
来源 App → 快捷指令截屏 → 与“屏幕翻译”共享
                           ↓
                系统宿主中的全屏 Action 扩展
                           ↓
          Vision → Apple Translation / 自选 AI → 原位覆盖
                           ↓
             × 或从靠近底部的图片区域上滑
                           ↓
              completeRequest → 返回来源宿主
```

扩展不把主 App 启到前台，也不返回 Siri 结果卡片。`NSItemProvider` 提供截图，画面延伸到扩展边缘，无自定义导航栏和底部工具栏；保留原图、更多和叉号。关闭或应用内上滑手势结束扩展请求，由系统恢复来源宿主。

这是系统提供的临时全屏翻译界面，输入仍是一张截图。没有添加任意 App 的永久透明窗口或实时录屏，不使用私有挂起、退出或 SpringBoard 接口。系统 Home 手势、Shortcuts 的唤起动画及宿主差异仍需真机验收。

旧 `TranslateScreenshotIntent` 保留类型以兼容既有指令，但改为明确的“在 App 中翻译截图”备用入口，不再调用片段。需要本次效果时应更换为“截屏 → 与屏幕翻译共享”。

## Siri 跑马灯说明

截图中的指令没有 Apple Intelligence“使用模型”动作。仅凭边缘灯效不能判断翻译是否由 Siri/Apple Intelligence 执行。系统通过 Shortcuts/Siri 呈现界面时可以出现自己的动画；本 App 不绘制模拟 Siri 灯效，也不依赖 Apple Intelligence 资格来调用 Vision 或 Translation。

## 苹果语言模型

删除后台片段仅允许“已安装模型”的门槛，改由可呈现 UI 的扩展运行系统 `translationTask`，让系统处理首次模型下载/授权。

“语言不支持”和“模型未安装”不是一回事。失败后检查语言对是否为 `unsupported`，明确提示更换语言或选择 AI，不再统一提示“先去主 App 准备模型”。用户示例包含巴斯克语内容；苹果支持的语言范围与 Vision 能识别的语言范围并不相同。不能承诺下载模型即可解决任何语言，也不会自动把不支持的文本发往云端。

## 设置与凭据共享

主 App 和扩展使用同一个 App Group，保存非敏感配置和用户自愿保存的历史。升级时迁移原有配置；旧历史复制成功后才删除旧文件。回到主 App 会刷新跨进程设置。

两个 target 声明相同的默认 Keychain 组，服务名取实际的主 App Bundle ID。由 iOS 解析签名团队前缀，避免未签名 IPA 的构建前缀在重新签名后失效。API Key 不写入 App Group 配置、模板、日志或源码。

侧载签名应同时保留主 App、`.appex`、App Groups 和共享 Keychain 权限。如果签名工具去掉 App Group，扩展仍能使用自己的本地设置及免费 Apple 引擎，但不能与主 App 同步配置，设置页会说明这一点；不能将主 App 里看不到的凭据说成已同步。

## 语言、图标和历史入口

默认界面语言为跟随系统，保留用户明确选择的旧设置。支持简体中文、繁体中文、English、Español、日本語、한국어、Français、Deutsch、Italiano、Português、Русский、العربية；选项以自己的语言显示，阿拉伯语使用 RTL。新增文案在本地离线生成并校对，App 不附带翻译资源生成模型或调用第三方文案翻译服务。

`AppIcon.appiconset` 中加入 1024×1024 不透明图标，iOS 负责圆角裁切。保存历史默认关闭，底部历史标签仅在开启时显示；关闭或从扩展改回关闭时，主 App 刷新并退出已失效的历史标签。

## 自动导入的实际限制

导入准备好的快捷指令仍需要 iOS 的“添加快捷指令”确认，不能静默代替用户批准或修改操作按钮绑定。

已经加入内置文件导入器（`UIDocumentInteractionController`）和无云端依赖的本地文件交付方式。没有使用指向普通文件服务器的 `shortcuts://import-shortcut?url=…`：现有 iOS 26.5 的[公开实测实现](https://github.com/manuogm/keepo-app/blob/main/App/Services/ShortcutsInstaller.swift)报告该路径仅接受 iCloud URL，普通文件网址会在下载前被拒绝。

**当前仍缺可分发的签名文件。** 本环境在 macOS Actions 实测 `shortcuts sign --mode anyone` 返回 `In order to do this, you must be signed into iCloud.`，且没有生成签名文件。该命令可能在没有文件时仍返回 0，所以脚本会额外检查文件存在及 `AEA1` 头。公共签名服务也未成功；没有把占位字节或未签名 plist 冒充有效文件。

已提供可审阅的双动作模板 [TranslateScreen.unsigned.plist](../Shortcuts/TranslateScreen.unsigned.plist) 与 [sign-shortcut.sh](../tools/sign-shortcut.sh)。共享动作采用 `is.workflow.actions.runextension`、`WFAppIdentifier` 和前一步输出的 `WFInput`，参数依据包括[公开导出语料](https://github.com/anupml/unqforge/blob/29009cf77bcac75a7630aa7cbe4573c227e7e6fc/docs/actions.md#isworkflowactionsrunextension)；不把扩展 Bundle ID 凭空当作系统动作 ID。维护者需在已登录 iCloud 的 Mac 签名一次，并在 Shortcuts 中确认扩展动作可解析，再将输出的 `ScreenTranslate/Resources/TranslateScreen.shortcut` 纳入构建。如果侧载修改了主 App Bundle ID，模板中的 `WFAppIdentifier` 也须匹配。之后消费者只需点导入并作系统确认，无需自己拼装动作。在这之前，当前构建明确禁用自动导入，并保留两动作手工设置，不宣称第 7 项已经完成。

## 验证

除了生产核心测试，还增加真实系统活动面板的 UI 测试：分享测试图片给已嵌入的扩展，检查画面覆盖屏幕、符号切换、上滑和叉号返回宿主；另一项检查历史标签随开关出现/隐藏。宿主测试覆盖真实图片提供器、扩展 Info.plist、图标、十二种语言资源及共享标识。

UI 测试使用来源宿主的固定输入和相同源/目标语言，以免假装模拟器已下载翻译模型。测试结果以对应提交的 Actions/PR 为准。真机仍须验证轻点背面/操作按钮、Siri 动画、实际语言包下载、混合语言、侧载签名权限与内存限额。
